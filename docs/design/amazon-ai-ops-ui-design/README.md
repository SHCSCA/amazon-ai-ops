# Amazon AI Ops 全量界面设计稿

> 历史文档（2026-10-27 归类）：以下计划、完成声明、计数、包哈希及 READY 只描述原阶段，不代表当前版本。现行状态及后续工作见 [项目状态](../../PROJECT_STATUS.md)；保留正文供追溯，不自动重新执行旧计划。

此目录按当前仓库的工作区注册表整理 Windows 桌面端界面。它是静态交互设计预览，覆盖 10 个工作区、22 个子页面；顶部的范围编辑、侧栏导航、页面标签和表格行可用于浏览稿件结构。

打开 [全量界面预览](./index.html) 查看设计稿。预览数据是结构示例，不连接本地数据库、领星、Amazon Ads、AI 服务或正式执行入口。

## 项目分析

- 产品为本地优先的 Electron 桌面工作台，主要用户是 Amazon 店铺运营人员；主要目标是从店铺事实进入诊断与决策，再到独立审批、真实执行、结果回读和实验结论。
- Renderer 的导航以 `MISSION_CONTROL_WORKSPACE_REGISTRY` 为准。旧页面通过显式兼容适配承接，生产页面状态和开发预览状态不能混为一谈。
- 主界面的关键约束是店铺范围隔离、数据来源可追溯、候选与对象版本绑定、审批和执行分离、未知写入结果需要人工对账、Listing 草案仅本地预览。
- 仓库已有任务优先工作台方向和浅色设计令牌。本稿延续该方向，采用一个明确的下一步任务、紧凑事实摘要和一个主要对象队列；不将所有功能堆进指标卡或把技术诊断放在首屏。

## 全局布局

1. **顶栏**：产品名称、当前店铺范围、设计预览标记和账户入口。范围始终可见；修改范围使用弹窗，不挤动当前页面。
2. **侧栏**：按工作区分组，仅当前工作区展开对应子页面；当前路由同时有文字和位置状态。
3. **页面头部**：一个页面主标题、一句说明和轻量刷新入口。
4. **工作区标签**：只呈现当前工作区的子页面。
5. **任务横幅**：说明当前主任务、关键边界和一个主动作。
6. **摘要条**：最多四项，优先展示数量、时效或授权状态；没有权威数据时显示等待/未核验状态。
7. **对象队列**：每页的主要工作区。行聚焦业务对象，证据来源和状态清晰可见；复杂解释放入详情检查器。
8. **详情检查器**：展示与当前对象相关的来源、身份、版本、时间窗口、决策理由或修复入口。

## 22 个页面草图

每个条目对应预览中的一个可选页面。预览使用同一套应用外壳，但针对页面更换任务、摘要、主对象队列和说明。

| 页面 | 首屏结构与主区域 | 重点状态 / 操作 |
| --- | --- | --- |
| 今日总览 | 今日任务链、执行前检查、关键对象队列 | 先处理下一安全动作；缺少权威投影时显示阻塞原因 |
| 运营事件 | 事件时间、影响对象与记录队列 | 事件只记录经营背景，不直接写入 Ads |
| 运营任务队列 | 目标与约束摘要、任务检查点、停驻原因 | 显示当前检查点；不从预览数据创建生产任务 |
| 广告事实 | 广告对象、指标区间、报表与身份核验 | 同名对象按 ID 分开；来源批次可展开 |
| 待判断 | 建议队列与对象详情 | 先核验对象版本、建议幅度和证据有效性 |
| 待审批 | 具体候选、当前值/建议值、风险和授权边界 | 批准与拒绝需明确候选和理由；审批不等于执行 |
| 已处理 | 决策历史与候选后续状态 | 只读；将决定、执行与回读分别显示 |
| 实验台账 | 假设、变量、观察窗口和效果列 | 按已完成业务日观察，证据齐全后再生成结论 |
| 可见执行 | 当前浏览器会话、串行执行步骤和未知结果队列 | 会话失效或结果不确定时停止并转人工对账 |
| 执行回读 | 执行前、执行后、刷新回读与证据工作区 | 缺项逐步修复；不能用 UI 状态替代真实读回 |
| 因果时间线 | 按对象串联事实、分析、决定、行动和效果 | 点击节点查来源；历史记录只读 |
| 产品与目标 | 产品队列、价格成本、目标字段和行内保存状态 | 目标 ACOS、TACOS、最低价、净利率字段各自命名 |
| 广告对象 | Campaign → Ad Group → Target → Search Term 层级 | 对象 ID、启停状态和匹配方式作为身份依据 |
| 关键词事实 | 关键词表、匹配方式、趋势与机会信号 | 机会解释须显示数据日期和来源；不代表执行授权 |
| Listing 内容 | 当前内容与本地草案并列、版本差异 | 明确“仅本地预览”；不会自动覆盖线上 Listing |
| 采集范围 | 店铺、站点、日期和产品范围表单 | 保存后首屏回显范围及业务时区 |
| 采集任务 | 八类报表状态与可见浏览器任务进度 | 每类独立显示成功/失败、文件回执和恢复动作 |
| 导入检查 | 报表批次、记录数、模式与指标校验表 | 缺失、重复、错期分开列示；分析入口受门槛控制 |
| 策略边界 | 策略版本、模式、范围、限额和熔断状态 | 启用或发布前展示变更影响，并在执行前重校验 |
| AI 与本地 | AI 连接、成本上限、凭证状态和本地配置 | 秘密不回传 Renderer；连接成功状态需实测 |
| 定时任务 | 店铺级计划、最近运行和下一次运行列表 | 忙碌、失败、停用分别表达；不以计划状态表示成功 |
| 交付验收 | 当前候选的条件清单、匹配证据和阻塞项 | 仅当前候选证据可计入；不以历史百分比或哈希代替验收 |

## 视觉与组件规范

- **工作面**：Windows 桌面 1440×900 为主稿尺寸；在 1200px 宽和 Windows 125% 缩放下允许顶栏折行，不能覆盖正文或操作按钮。
- **颜色**：浅灰画布、白色主工作面、深蓝主动作；绿色只表示已由权威来源确认，琥珀表示待处理，红色表示阻塞或风险。无权威状态使用中性色和原因说明。
- **文字**：页面标题 24/32px，区段标题 16/24px，正文 14/21px，表格与控件 13/20px，辅助说明不低于 12/18px；数值使用等宽数字对齐。
- **间距与边界**：采用 4/8/12/16/24/32px 间距；工作区以分组、留白和细分隔线为主。阴影仅用于弹窗、浮层等空间层级。
- **交互反馈**：页面导航、行选择和面板显隐使用 120–180ms；只对真实加载使用持续动效；支持减少动态效果偏好。
- **无障碍**：真实按钮和链接、清晰焦点环、表格键盘聚焦、适当 `aria-live`、选项卡语义、弹窗关闭与焦点恢复。

## 全局状态稿

所有适用页面至少包含以下状态定义；真实实现按权威投影决定状态，不允许由按钮点击直接宣称业务成功。

- **加载**：任务标题保留；在主队列显示稳定骨架和“正在读取当前店铺数据”。
- **空状态**：指出当前没有记录，并保留唯一合理的下一步入口。
- **待确认**：展示缺少的范围、来源、对象身份或审批条件。
- **阻塞**：说明具体原因、受影响动作和可修复入口；阻塞动作禁用并可读。
- **忙碌**：仅活动动作显示运行中状态，相关竞争动作被锁定。
- **失败**：保留已输入草稿，显示可操作错误与重试/修复入口。
- **成功**：只在重新读取到权威结果后显示确认状态。
