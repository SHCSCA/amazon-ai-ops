## 设计定位

这是跨境 Amazon 广告运营后台，不是营销页。界面目标是让用户明确知道：

1. 当前运营范围是什么。
2. 当前是否有真实领星广告原始报表。
3. 下一步应该做什么。
4. 哪些页面是业务操作，哪些只是证据或技术诊断。
5. 广告量化、建议、审批、执行回读之间的顺序关系。

## 视觉系统

- 风格：企业级运营控制台。
- 密度：中高，但首屏只保留业务判断、下一步和关键指标。
- 色彩：浅灰工作区、白色面板、深蓝顶部栏、蓝色主操作、绿/黄/红只用于状态。
- 形状：统一 8px 圆角。
- 阴影：轻量阴影，只用于主面板和工作流卡片。
- 字体：Windows 后台优先使用 Segoe UI / Microsoft YaHei / system-ui。

## 信息架构

侧边栏按真实业务流分组：

- 运营总览
  - 仪表盘
- 数据与量化
  - 数据采集
  - 广告量化
- 广告执行
  - 优化建议
  - 审批中心
  - 执行回读
- 关键词与 Listing
  - 关键词机会
  - Listing 优化
- 系统与交付
  - 定时任务
  - 设置
  - 交付验收

## 页面骨架

每个主页面固定为：

1. 当前运营范围条。
2. 页面头：页面职责、主任务、下一步。
3. 首屏健康/门槛：当前范围、真实数据、AI 状态、待处理业务数量。
4. 主工作区：只放当前页面的核心动作。
5. 结果/证据区：显示文件、表格、路径。
6. 技术细节：必须折叠展示，默认不占主视觉。

## 关键约束

- 没有真实 `.xlsx/.xls/.csv` 原始报表时，不能展示为“广告数据已可用”。
- 审计 JSON、截图、HTML、DOM、Manifest 不能计入广告数据。
- 货币统一使用 USD。
- 技术命令、验证矩阵、原始 JSON 不放首屏。
- APP_READY / APP_NEEDS_WORK 等原始状态码不直接展示给运营用户，必须翻译成“可交付/未就绪”等业务文案。
- 广告动作必须经过建议、审批、执行回读，不能在建议页直接写入。
