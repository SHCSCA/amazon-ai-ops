## Remaining Manual Gate

The only major blocker is the real Lingxing download center action model. The real Ads URL, read-only list page, and create-report setup selectors have been verified, but the implementation intentionally keeps `requiresManualVerification: true` until these items are verified against the live Lingxing UI and saved through a same-model diagnostic:

- store selector action flow through a real generate attempt, including the already-selected-store case
- report type dropdown action flow for each of the 8 report types
- date range controls, including both start and end date selectors plus Lingxing Vue/Element state update
- create report button and any confirm/result dialog
- generation status indicator
- report/date-scoped ready row selector
- report/date-scoped download button
- browser download behavior and final filenames
- desktop UI `验证页面` rerun after a stable Lingxing login/Ads session, to refresh same-model/date/store/site evidence from the current build; renderer clickability itself is covered by local QA evidence

Once these selectors are confirmed, save them as the local download-center page-model override and only then consider setting `requiresManualVerification` to `false`. The existing collector port will then use the selector-driven Playwright actions. Local overrides are validated on save and read; invalid overrides are reported in the UI and the bundled model is shown for recovery.

The current app includes a read-only `验证页面` action to gather this evidence from the logged-in browser without creating reports or downloading files, including Playwright visible-locator counts and usability/ambiguity labels for action selectors. It also includes `导出证据包` to save the diagnostic, page model, screenshot/DOM evidence, and checklist into a local export folder, plus a local page-model JSON editor for saving the verified override without rebuilding the app.
