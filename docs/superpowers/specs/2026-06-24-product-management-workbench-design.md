# 产品管理工作台设计规格

日期：2026-06-24

## 背景

当前应用已经具备产品配置、运营事件、产品广告历史账本、广告量化按 ASIN 分组、优化建议和 Listing/关键词相关能力，但这些能力分散在不同页面。用户在多个页面直接看到 ASIN，无法快速判断 ASIN 对应的真实产品，也难以围绕单个产品串联广告数据、运营事件、AI 量化、关键词和 Listing。

截图中的运营事件时间线暴露了核心问题：事件按时间展示，但“影响待观察 / 全店/全范围”缺少产品语义；产品事件、全局事件和广告对象事件混在同一平面，用户无法按产品管理运营时间线，也无法判断这些事件如何影响 AI 广告量化。

## 目标

1. 新增一级产品视角入口，让用户先选择产品，再查看广告表现、运营事件、AI 量化、关键词和 Listing。
2. 用产品标题、ASIN、SKU/MSKU、阶段、状态和关键指标解释 ASIN，避免用户只看到裸 ASIN。
3. 支持按产品切换运营时间线；产品视图中显示当前产品事件，并按日期插入全局事件。
4. 保留全局事件视图；全局视图只显示全店/全范围事件，不混入产品事件。
5. 产品选择应同步当前 `scope.asin`，让广告量化、优化建议、运营事件、关键词机会和 Listing 优化默认围绕该产品。
6. 第一版复用现有 SQLite、本地数据、React 页面和 CSS 组件，不引入新依赖，不改变广告执行 fail-closed 边界。

## 非目标

1. 不自动从 Amazon 或 Lingxing 新增产品主数据同步接口。
2. 不自动执行广告动作，不改变审批、截图和回读要求。
3. 不做移动端适配；只面向 Windows 桌面应用。
4. 不把产品管理做成营销首页或大面积装饰性卡片。
5. 不重写现有数据采集、导入、广告量化和建议生成算法，只调整产品入口、关联和展示语义。

## 当前基础

已有能力：

- `products` 表保存 ASIN、标题、SKU/MSKU、阶段、状态和成本目标。
- `operation_events` 表保存事件日期、店铺、站点、ASIN、广告活动、广告组、事件类型、影响预期、备注和证据路径。
- `BusinessDataPipeline` 已返回 `productContext`、`operations` 和 `productHistory.ledgers`。
- `AdQuantPage` 已有按 ASIN 分组查看能力。
- `OperationScope` 已支持 `asin`。
- `ProductConfigPage` 已能维护产品阶段、成本、目标 ACOS/TACOS 和利润约束。

关键缺口：

- 产品配置不是产品工作台，只能维护参数，不能承载产品级决策。
- `AdQuantPage` 的产品选择只是局部状态，不会同步全局 `scope.asin`。
- 当前按 ASIN 查询运营事件时只返回该 ASIN 事件，产品时间线会漏掉全局事件。
- 导航中产品入口位于 `数据与量化` 的辅助位置，用户仍从数据或 ASIN 开始工作。

## 产品管理页面

页面结构为 `产品列表 + 产品详情工作台`。

### 产品列表

产品列表用于快速识别和切换产品。每一行或每个紧凑产品项显示：

- 产品标题
- ASIN
- SKU/MSKU
- 产品阶段
- 状态
- 花费
- 销售
- 订单
- ACOS
- 事件数

排序默认按当前范围花费降序，其次按高风险对象数量、事件数量、标题/ASIN 排序。若当前范围无广告数据，则按产品更新时间展示。

空状态：

- 无产品配置：提示先创建产品配置，可从当前 ASIN 或 Listing 数据创建。
- 有广告数据但产品配置为空：根据广告数据中的 ASIN 生成“待补全产品”列表，显示 ASIN 和指标，提示补标题/SKU/阶段。
- 有产品但当前范围无广告数据：显示产品基础信息和“当前范围暂无广告指标”。

### 产品详情工作台

选中产品后展示以下区域：

1. `产品身份`
   显示标题、ASIN、SKU/MSKU、父 ASIN、阶段、状态、目标 ACOS/TACOS、最低价和目标净利率。

2. `广告表现`
   使用当前范围的产品广告历史账本或广告量化分组，显示花费、销售、订单、ACOS、CVR、CPC、高风险对象、可建议对象数量。

3. `运营时间线`
   默认显示当前产品视图：当前产品事件 + 全局事件按日期混排。事件必须有视觉标签区分 `产品`、`全局`、`广告对象`。

4. `AI 量化入口`
   显示 AI 是否可运行、真实报表覆盖、导入指标、产品目标是否完整，并提供进入 `量化诊断中心` 和 `优化建议草案` 的动作。

5. `关键词与 Listing`
   提供进入 `关键词机会矩阵`、`Listing 结构重写` 的动作，并沿用当前产品 ASIN。

6. `成本与目标`
   内嵌现有产品配置编辑能力，维护阶段、状态、成本、最低价、目标净利率、目标 ACOS 和目标 TACOS。

## 产品上下文联动

产品管理中选中产品时，更新全局 `scope.asin` 为该产品 ASIN，并保持当前日期、店铺、站点、币种和批次不变。

联动结果：

- `ScopeBar` 的 ASIN 显示为产品标题 + ASIN，而不是只有 ASIN。
- `广告量化` 默认过滤到该产品。
- `优化建议` 默认生成该产品建议。
- `运营事件` 默认新建为当前产品事件，但允许切换为全局事件。
- `关键词机会` 默认显示当前产品关键词。
- `Listing 优化` 默认读取当前产品 Listing。

当用户清空产品选择时，`scope.asin` 清空，各页面恢复全部产品视图。

## 事件模型与时间线规则

事件作用范围分三类：

1. `全局事件`
   `asin`、`campaignName`、`adGroupName` 均为空。影响全店或全范围，例如大促、账号级活动、全店预算策略。

2. `产品事件`
   绑定 `asin`，可选绑定广告活动或广告组。例如某 ASIN 开 Coupon、调价、Listing 修改、库存异常。

3. `广告对象事件`
   绑定 `campaignName` 或 `adGroupName`，可选绑定 `asin`。用于解释广告结构变化。

查询语义：

- 全局事件视图只返回全局事件。
- 产品事件视图返回：
  - 当前产品事件；
  - 当前产品广告对象事件；
  - 同日期范围、同店铺、同站点的全局事件。
- 全部事件视图返回当前范围内所有事件，但必须可按范围标签筛选。

产品时间线排序：

- 按 `eventDate` 倒序展示。
- 同一天内优先展示产品事件，再展示广告对象事件，再展示全局事件。
- 每条事件显示范围标签、事件类型、影响预期、标题、备注和证据路径。

新增事件交互：

- 新建事件时先选择作用范围：`全局`、`当前产品`、`广告对象`。
- 若在产品管理页新建，默认选择 `当前产品` 并填充当前 ASIN。
- 若在全局事件视图新建，默认选择 `全局`。
- 广告对象事件必须显式填写 campaign 或 ad group，避免用户误以为它是全局事件。

## 数据与接口调整

新增或调整的前端派生函数：

- 构建产品列表摘要：从 `productContext.products`、`productHistory.ledgers`、`quant.diagnostics`、`operations.events` 合并产品身份和指标。
- 构建产品时间线：输入当前 ASIN、事件列表，输出全局/产品/广告对象分类与排序后的事件。
- 产品选择同步：选择产品后调用 `setScope({ asin })`。

后端/仓储语义调整：

- 保留现有 `findByScope` 行为，避免破坏已有调用。
- 新增产品时间线专用查询或在主进程组合查询：
  - `listGlobalOperationEvents(scope)`
  - `listProductOperationEvents(scope, asin, includeGlobal=true)`
- `getBusinessUiDataPipeline(scope)` 在 scope 带 ASIN 时，产品历史账本应包含产品事件和全局事件，避免 AI 量化漏掉大促、全店活动等背景。

## 页面状态

产品管理必须覆盖：

- Loading：读取产品、指标、事件和产品历史账本。
- Empty：无产品配置时，提示创建或从广告数据中的 ASIN 补全。
- Ready：有产品、有广告指标、有事件或无事件但可继续分析。
- Partial：有产品但缺广告数据，或有广告数据但缺产品标题/成本目标。
- Error：产品/事件/数据管道读取失败，显示中文错误和重试入口。
- Disabled：无真实报表或无导入指标时，AI 量化/优化建议按钮禁用并说明原因。

## UI 体验约束

Visual thesis：

产品管理页是“产品作战台”，让运营先定位产品，再理解广告表现、事件背景和 AI 判断。

Primary workspace：

产品列表用于切换，产品详情用于决策。页面优先使用紧凑表格、标签、时间线和操作区，不使用大面积装饰卡片。

Core interaction：

选择产品 -> 更新 `scope.asin` -> 产品详情、广告量化、运营事件、优化建议、关键词和 Listing 跟随。

Motion purpose：

只使用轻量 CSS hover/focus/active 状态和必要的展开折叠，不引入新动画依赖。

State coverage：

无产品、无广告、无事件、只有全局事件、有产品事件、AI 不可用、数据阻断都必须有明确中文提示。

Implementation boundary：

第一版使用现有 React、Zustand、SQLite、IPC 和 CSS token。不要增加 Three.js、GSAP 或其他视觉依赖。

## 验收标准

1. 左侧导航出现 `产品管理`，用户可以从产品视角进入工作。
2. 产品列表至少能显示已有产品配置，并能用产品标题和 ASIN 识别产品。
3. 选中产品后 `scope.asin` 更新，`ScopeBar` 能体现当前产品上下文。
4. 产品详情能展示当前产品广告概览、产品阶段/目标、运营事件时间线和跳转动作。
5. 产品时间线能同时显示当前产品事件和全局事件，并用标签区分。
6. 全局事件视图只显示全局事件，不混入产品事件。
7. 新增事件时能选择全局、当前产品或广告对象范围。
8. 广告量化、优化建议、关键词机会和 Listing 优化能沿用当前产品 ASIN。
9. 保留广告执行 fail-closed，不新增任何自动广告写入。
10. 相关单元测试和类型检查通过；涉及 UI 的 smoke 测试覆盖导航、产品管理入口、产品选择、时间线分类和关键跳转。

## 测试计划

单元测试：

- 产品列表摘要合并产品配置、广告指标、产品历史账本和事件计数。
- 产品选择更新 `scope.asin`。
- 产品时间线合并产品事件和全局事件，并按日期排序。
- 全局事件视图只保留全局事件。
- 事件新建默认范围在产品页为当前产品，在全局事件页为全局。

仓储/主进程测试：

- 产品视图查询包含当前 ASIN 事件和全局事件。
- 全局视图查询不包含产品事件。
- 带 ASIN 的业务数据管道保留全局事件供产品历史账本和 AI 上下文使用。

渲染测试：

- 导航显示 `产品管理`。
- 产品管理页显示产品标题、ASIN、广告概览和事件标签。
- 从产品管理跳转广告量化/优化建议/Listing 时保留当前产品 ASIN。

最终验证：

- `pnpm exec vitest run` 覆盖新增和相关测试。
- `pnpm --filter @amazon-ai-ops/desktop run typecheck`。
- 产品管理相关业务 UI smoke。
- 若改动进入交付包，按项目要求重新 `build:win` 并生成新的 portable/no-install EXE。
